Power BI Fundamentals & Interface
Beginner⌢
📚 Overview

Power BI is Microsoft's business analytics platform. Master: Desktop (authoring), Service (cloud), Mobile (consumption). Data flow: connect → transform → model → visualize → share.

🎯 Key Points
  • Power BI Desktop = local authoring with Power Query & DAX
  • Power BI Service = cloud platform for publishing & collaboration
  • Power BI Mobile = consume dashboards on phones
  • Ribbon tabs: Home, Insert, Modeling, View, Help
  • Key panes: Fields, Visualizations, Filters, Format
Practice Questions
Q1. What's the difference between Desktop and Service?Show
Desktop: local authoring. Service: cloud publishing, sharing, refresh schedules.
Q2. What is the data flow in Power BI?Show
Data Source → Power Query (clean) → Model (relate) → Visualizations (display) → Service (share)
Q3. How do you access Power BI?Show
Desktop (download from microsoft.com), Service (cloud.powerbi.com on browser), Mobile (phone app)
💡 Detailed Examples

📌 Example: First Time Setup

Step 1: Download Power BI Desktop from microsoft.com

Step 2: Sign in with Microsoft account

Step 3: Create new report

Step 4: Explore interface: Home tab, Insert visuals, View options

Pro tip: Right-click fields to add to visualization

📌 Example: Dashboard vs Report

Dashboard: One-page snapshot of KPIs (5-10 visuals max). Executive summary.

Report: Multi-page detailed analysis (50+ pages possible). Deep dives into metrics.

Use dashboards for execs, reports for analysts

Data Sources & Connectivity
Beginner⌢
📚 Overview

Connect to: Excel, CSV, SQL databases, cloud services, APIs, web pages. Understand: Import vs DirectQuery vs Live. Each has trade-offs.

🎯 Key Points
  • Import: copy data into Power BI (fastest queries, no live updates)
  • DirectQuery: query source directly (real-time, no storage)
  • Live connection: connect to published models or Analysis Services
  • Authentication: credentials, OAuth, service principal
  • Incremental refresh: only get new/changed data
Practice Questions
Q1. When to use Import vs DirectQuery?Show
Import: <1GB, frequent analysis, offline work. DirectQuery: massive data, real-time needed.
Q2. What is incremental refresh?Show
Only load new data instead of full refresh. Saves bandwidth. Essential for big datasets.
Q3. How to connect securely?Show
Use service principal or Windows auth. Encrypt credentials. Gateway for on-prem. RLS for sensitive data.
💡 Detailed Examples

📌 Example: Import CSV File

  1. Home → Get Data → CSV
  2. Select file from computer
  3. Preview data appears
  4. Click Load to import
  5. Data appears in Fields pane

📌 Example: Connect to SQL Server

  1. Home → Get Data → SQL Server
  2. Enter server name: server.database.windows.net
  3. Select database and table
  4. If on-prem: configure Power BI Gateway
  5. Choose Import or DirectQuery

📌 Example: Incremental Refresh Setup

Setup: Range between RangeStart and RangeEnd parameters

let Source = Sql.Database("server", "db"), FilteredData = Table.SelectRows(Source, each [Date] >= RangeStart and [Date] < RangeEnd) in FilteredData

Power BI automatically increments dates on refresh

Power Query: Data Cleaning & Transformation
Beginner⌢
📚 Overview

Power Query is ETL engine using M language. Clean messy data: remove nulls, duplicates, split columns, merge tables. Applied steps create reproducible transformations.

🎯 Key Points
  • Remove nulls & duplicates (Home tab)
  • Split columns (by delimiter or position)
  • Merge queries (join: inner, outer, left, right)
  • Append queries (union: stack tables)
  • Unpivot: convert wide to long format
  • Applied Steps: track & edit transformations
Practice Questions
Q1. Merge vs Append?Show
Merge = join horizontally. Append = stack vertically.
Q2. How to split address into street, city?Show
Split Column → By Delimiter (comma). Creates separate columns.
Q3. What if I edit an earlier Applied Step?Show
All dependent steps re-execute automatically. Powerful!
💡 Detailed Examples

📌 Example: Clean Sales Data

Original data issues: nulls, 'APPLE' vs 'Apple', text prices '100.50'

  1. Remove rows where Quantity is null
  2. Standardize ProductName: Text.Upper([Product])
  3. Convert Price from text to number
  4. Remove duplicates on Date+Product
  5. Create Amount column: [Quantity] * [Price]

📌 Example: Merge Sales with Products

Sales table: [SalesID, ProductID, Quantity] Products table: [ProductID, ProductName, Category] Merge: Home → Merge Queries Sales[ProductID] = Products[ProductID] Join Kind: Left Outer Result: Sales now has ProductName & Category

📌 Example: Unpivot Monthly Sales

Wide format: Columns: ProductID, Jan, Feb, Mar

Long format (after unpivot): ProductID, Month, Sales

Power Query → Unpivot Other Columns

Enables time series analysis

Data Modeling & Relationships
Beginner⌢
📚 Overview

Data model is backbone. Create relationships between tables. Star schema: fact (measurements) + dimensions (descriptors). Proper relationships enable accurate calculations.

🎯 Key Points
  • Star schema: fact + dimensions
  • Cardinality: 1-to-1, 1-to-many, many-to-many
  • Active vs inactive relationships
  • Cross-filter direction: one-way or both
  • Hide fields from report builders
  • Avoid cycles in relationships
Practice Questions
Q1. Star schema example?Show
Fact: Sales[revenue, quantity]. Dimensions: Date, Product, Customer. Fact surrounded by dimensions.
Q2. Cardinality?Show
1-to-many: 1 customer → many orders. Effects filtering and aggregation.
Q3. Hidden fields?Show
Hide keys, helper columns. Simplify report builder interface.
💡 Detailed Examples

📌 Example: Build Star Schema for Retail

Tables created:

FACT: Sales[SalesID, Date, ProductID, StoreID, CustomerID, Amount] DIM: Products[ProductID, Name, Category, Price] DIM: Stores[StoreID, Name, Region] DIM: Customers[CustomerID, Name, Segment] DIM: Calendar[Date, Month, Year, Quarter]

Relationships: Sales→Products, Sales→Stores, Sales→Customers, Sales→Calendar (1-to-many)

📌 Example: Set Active Relationship

Model view: drag ProductID from Sales to Products. Creates 1-to-many.

If multiple Date fields: OrderDate (active) vs ShipDate (inactive)

Measures use active automatically. Use USERELATIONSHIP() for inactive.

📌 Example: Cardinality & Impact

1-to-many: Sales[ProductID] → Products[ProductID]

Filter: clicking Product filters Sales by that product ✓

Many-to-many: requires bridge table (e.g., Student→Enrollment→Course)

Cardinality wrong = calculation errors

Introduction to DAX: Basic Measures & Columns
Beginner⌢
📚 Overview

DAX (Data Analysis Expressions) is calculation language. Measures (aggregates), calculated columns (row-level). Master: SUM, AVERAGE, COUNT, FILTER, CALCULATE.

🎯 Key Points
  • Calculated columns: row-by-row, computed at refresh
  • Measures: aggregate level, computed when displayed
  • Functions: SUM, COUNT, AVERAGE, COUNTA, DISTINCTCOUNT
  • Implicit vs explicit measures
  • FILTER: subset data
  • CALCULATE: change filter context
Practice Questions
Q1. Column vs Measure?Show
Column: storage, row-level. Measure: no storage, aggregate level. Use measures.
Q2. When use CALCULATE?Show
Modify filter context. YTD sales, previous month, all-time average.
Q3. Write: Total Sales measureShow
Total Sales = SUM(Sales[Amount]) Basic aggregation.
💡 Detailed Examples

📌 Example: Basic Measures

Total Revenue = SUM(Sales[Amount]) Total Quantity = SUM(Sales[Quantity]) Average Price = AVERAGE(Sales[Price]) Transaction Count = COUNTA(Sales[SalesID]) Unique Customers = DISTINCTCOUNT(Sales[CustomerID])

📌 Example: Calculated Column

// Add to Sales table Profit Margin = DIVIDE( [Amount] - ([Quantity] * RELATED(Products[CostPrice])), [Amount] ) // Row-by-row: each sale has margin calculated

📌 Example: Measure with CALCULATE

// Last Year Revenue Last Year Revenue = CALCULATE( [Total Revenue], ALL(Calendar), Calendar[Year] = MAX(Calendar[Year]) - 1 ) // Removes all filters, applies specific year

Advanced DAX: Context, Variables, Iterators
Intermediate⌢
📚 Overview

Master filter context and row context. Use variables for reusable calculations. Iterators for row-by-row logic.

🎯 Key Points
  • Filter context: filters from slicer/report
  • Row context: current row
  • CALCULATE modifies context
  • VAR stores intermediate values
  • SUMX, AVERAGEX iterate rows
Practice Questions
Q1. Filter vs row context?Show
Filter: affects aggregations. Row: affects individual rows.
Q2. What does CALCULATE do?Show
Change filter context for calculation.
💡 Detailed Examples

📌 Example: YTD (Year-to-Date) Measure

Revenue YTD = CALCULATE( [Total Revenue], DATESYTD(Calendar[Date]) ) // Cumulative from Jan 1 to today

📌 Example: Moving Average with Variables

Moving Avg 3M = VAR CurrentDate = MAX(Calendar[Date]) VAR PriorMonths = CALCULATE( [Total Revenue], DATESINPERIOD(Calendar[Date], CurrentDate, -3, MONTH) ) RETURN PriorMonths / 3

Time Intelligence & Calendars
Intermediate⌢
📚 Overview

Time intelligence enables year-over-year, YTD, rolling totals. Create calendar table. Use DATEADD, SAMEPERIODLASTYEAR.

🎯 Key Points
  • Calendar table essential
  • Mark as date table
  • DATEADD shifts dates
  • SAMEPERIODLASTYEAR compares years
  • TOTALYTD cumulative total
Practice Questions
Q1. Why calendar table?Show
Ensures continuous dates. Enables time intelligence functions.
Q2. YoY comparison measure?Show
DIVIDE([Current Year Revenue], CALCULATE([Revenue], SAMEPERIODLASTYEAR(...)))
💡 Detailed Examples

📌 Example: Calendar Table Creation

Calendar = ADDCOLUMNS( CALENDARAUTO(), "Year", YEAR([Date]), "Month", MONTH([Date]), "Quarter", "Q" & QUARTER([Date]) ) // Then mark as Date Table in Model view

📌 Example: YoY Growth Measure

Revenue YoY Growth = DIVIDE( [Total Revenue] - [Last Year Revenue], [Last Year Revenue] ) // Returns % change vs prior year

Slowly Changing Dimensions (SCD)
Advanced⌢
📚 Overview

Track data changes over time. SCD Type 1/2/3. Maintain history for accurate time-period analysis.

🎯 Key Points
  • Type 1: overwrite (no history)
  • Type 2: track history (effective dates)
  • Type 3: current + previous
  • Surrogate keys
  • Effective dates
Practice Questions
Q1. SCD Type 2?Show
Insert new row when customer moves regions, old row ValidTo = today.
Q2. Why surrogate key?Show
Stable ID independent of business key.
💡 Detailed Examples

📌 Example: SCD Type 2 Customer Geography

Customers table: CustomerID (surrogate), Name, RegionID, ValidFrom, ValidTo When customer moves: Insert new row with new RegionID Old row ValidTo = today New row ValidFrom = today Query historical: filter by ValidFrom/ValidTo
