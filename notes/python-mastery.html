Variables, Data Types & Type System
Basics⌄
📖 Explanation

Python is dynamically typed — every value is an object with identity, type, and value. Core types: int (arbitrary precision, never overflows), float (64-bit IEEE 754), bool (subclass of int; True==1, False==0), str (immutable Unicode), bytes, and NoneType. Variable assignment binds a name to an object — it does not copy the value.

Python 3.8+ adds the walrus operator (:=) for assignment inside expressions. type(x) returns the exact class; isinstance(x, cls) checks the full inheritance chain.

int — unlimited precision; 0b1010 binary, 0xFF hex, 1_000_000 readable
float — 64-bit IEEE 754; 0.1+0.2 != 0.3; use Decimal for money
bool — subclass of int; True==1; every object has a truth value
str — immutable Unicode; f-strings fastest; triple-quotes multi-line
None — singleton; always use x is None, never x == None
type() vs isinstance() — type = exact; isinstance respects inheritance

Interview Questions
Q1. What is the difference between == and is?Reveal
Answer: == compares values (calls __eq__). is compares identity — same object in memory (same id()). [1,2] == [1,2] is True but [1,2] is [1,2] is False. Use is only for singleton checks: x is None, x is True. CPython caches small ints (-5 to 256) and interned strings, so is may accidentally be True for those — never rely on it.
Q2. Is Python pass-by-value or pass-by-reference?Reveal
Answer: Neither — pass-by-object-reference. Functions receive a reference to the same object. Mutable objects (list, dict): changes inside affect the caller. Immutable (int, str, tuple): rebinding locally has no effect. So def f(x): x += 1 doesn't change an int, but def f(lst): lst.append(1) modifies the original list.
Q3. Why does 0.1 + 0.2 != 0.3?Reveal
Answer: Floats use binary IEEE 754. Most decimal fractions can't be represented exactly in binary, so 0.1 + 0.2 is 0.30000000000000004. Fixes: round(0.1+0.2, 1) == 0.3, math.isclose(0.1+0.2, 0.3), or from decimal import Decimal; Decimal('0.1') + Decimal('0.2') for exact arithmetic (always use Decimal for money).

Interview Questions
Q1. Why is join() a method on the separator, not the list?Reveal
Answer: join() works on any iterable (list, tuple, generator), not just lists. The separator is the owner because it knows how to interleave itself. ','.join(items) means 'join items using comma as separator'. Also, all items must be strings — join validates this, which it would need to do regardless of whose method it was.
Q2. What is the difference between find() and index()?Reveal
Answer: Both return the starting index of the first occurrence. find() returns -1 if not found. index() raises ValueError. Use find() when absence is expected; index() when absence is a bug. For a simple existence check, prefer 'word' in text — clearest intent.
Q3. How do you reverse a string efficiently?Reveal
Answer: Use slice with step -1: s[::-1] — simple and fast. Or: ''.join(reversed(s)). The slice approach is idiomatic Python. Note: this reverses bytes; for multi-byte Unicode (emoji), be careful. Palindrome check: s == s[::-1].

Control Flow: if, for, while, match
Basics⌄
📖 Explanation

Python uses indentation to define blocks. if/elif/else for branching. The ternary expression: x if cond else y. for is always foreach — iterates any iterable. while for condition-based loops. break exits, continue skips. The for/while else clause runs only when no break occurred — Python's underused gem for search loops.

Python 3.10 added match/case — structural pattern matching supporting value, type, sequence, mapping, guard, and OR patterns. Far more powerful than chained if/elif.

Interview Questions
Q1. What does the else clause on a for loop do?Reveal
Answer: It runs when the loop completes without hitting a break. Think of it as 'nobreak'. Perfect for search: if found → break (else skipped). If loop exhausts without finding → else runs. Classic: for p in primes: if n%p==0: break; else: is_prime=True.
Q2. What is the difference between range() and list(range())?Reveal
Answer: range(1_000_000) is a lazy object using O(1) memory. list(range(1_000_000)) creates all million integers in RAM. range also does O(1) in checks: 500000 in range(1000000) is instant math. Only convert to list when you need to slice, index, or pass to something requiring a list.
Q3. How is match/case more powerful than if/elif?Reveal
Answer: match/case matches on structure, type, and value simultaneously. It supports: OR patterns (case 400 | 404), sequence destructuring (case [head, *tail]), mapping patterns (case {'key': val}), guard clauses (case x if x>0), and wildcard case _. Type checkers can verify exhaustiveness. if/elif only evaluates boolean expressions.

Functions: def, *args, **kwargs, scope
Basics⌄
📖 Explanation

Functions are first-class objects — assignable, passable, and returnable. Parameter order: positional, default, *args, keyword-only (after bare *), **kwargs. Python 3.8+ adds positional-only before /. The mutable default argument trap is Python's most famous gotcha: defaults are evaluated ONCE at definition time, not per call.

LEGB scope rule: Local → Enclosing → Global → Built-in. Reading travels up the chain automatically; writing requires global or nonlocal.

**kwargs — extra keyword args → dict

/ in sig — everything before is positional-only (3.8+)
LEGB rule — Local, Enclosing, Global, Built-in; global/nonlocal to write
Mutable default trap — use None sentinel; create mutable inside body

Interview Questions
Q1. What is the mutable default argument trap?Reveal
Answer: Default values are evaluated once at definition time, not per call. So def f(lst=[]) creates ONE list shared across all calls that don't pass lst. Each call accumulates items in the same object. Fix: use None as sentinel, create the mutable inside the body. Applies to any mutable default: list, dict, set, custom objects.
Q2. What is the difference between *args and **kwargs?Reveal
Answer: *args collects extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dict. Combined def f(*args, **kwargs) accepts any arguments — standard for wrapper functions that forward everything: wrapped(*args, **kwargs).
Q3. Explain LEGB with an example.Reveal
Answer: LEGB = Local → Enclosing → Global → Built-in. x='global'; def outer(): x='enclosing'; def inner(): print(x) — inner() prints 'enclosing'. To modify: global x writes to module level; nonlocal x in a nested function writes to the enclosing function's x. Without these, assignment always creates a new Local variable.

Exception Handling & Custom Exceptions
Basics⌄
📖 Explanation

Python uses try / except / else / finally. Catch the most specific exception first. else runs only when no exception occurred — separates success code from try. finally always runs — use for cleanup. Exception hierarchy: all inherit from BaseException; most from Exception; KeyboardInterrupt and SystemExit do not, so except Exception safely ignores Ctrl+C.

Built-in exceptions to know: ValueError, TypeError, KeyError, IndexError, AttributeError, NameError, RuntimeError, StopIteration, OSError/FileNotFoundError, ImportError, OverflowError, RecursionError, NotImplementedError, AssertionError, TimeoutError.

else — only runs if try succeeded; keeps success path clean
finally — always runs; even after return/break/continue
raise X from Y — exception chaining; preserves original cause
contextlib.suppress(Exc) — one-liner to silence specific exceptions

Interview Questions
Q1. What is the difference between Exception and BaseException?Reveal
Answer: BaseException is the root of all exceptions. Exception inherits from it and is the base for all regular program errors. KeyboardInterrupt, SystemExit, and GeneratorExit inherit from BaseException but NOT Exception. So except Exception won't catch Ctrl+C. Never use except BaseException unless you specifically need to handle exits/interrupts.
Q2. What is the purpose of the else clause in try/except?Reveal
Answer: else runs only when the try block raises no exception. It separates 'code that might fail' (in try) from 'code that should run on success' (in else). Without else, you'd put post-success code in try, where it could be accidentally caught by except. Pattern: open resource in try → use it in else → close it in finally.
Q3. When should you create a custom exception?Reveal
Answer: Create custom exceptions when: (1) your library needs domain-specific error types callers can catch selectively, (2) you want to attach metadata (field, error code, HTTP status), (3) you want one catch-all for all your library's errors. Always subclass an appropriate built-in: ValueError for bad input, RuntimeError for unexpected states, OSError for I/O.

Lists & List Methods
Data Structures⌄
📖 Explanation

Lists are mutable, ordered sequences of any objects. They support indexing, slicing, and all sequence operations. Internally a dynamic array. Key operations: append O(1), insert at index O(n), pop-from-end O(1), pop-from-middle O(n), index lookup O(1), membership test O(n). For frequent membership tests, use a set. For frequent front inserts/pops, use collections.deque.

List comprehensions are the Pythonic way to build lists — faster than equivalent for loops (optimised at C level). Nesting and filtering with if are supported. sorted() returns a new list; .sort() modifies in-place.

append(x) / extend(it) — append single; extend unpacks iterable
insert(i, x) — O(n); shifts elements; deque for front inserts
pop(i=-1) — O(1) from end; O(n) from middle; returns item
remove(x) — removes first occurrence; raises ValueError if absent
sort(key=fn, reverse=bool) — in-place Timsort; sorted() for new list
[expr for x in it if cond] — list comprehension; faster than for loop

Interview Questions
Q1. What is the time complexity of common list operations?Reveal
Answer:
  • append/pop() end: O(1) amortised
  • insert(i)/pop(i) middle: O(n) — shifts elements
  • x in lst: O(n) linear scan
  • lst[i]: O(1) index access
  • sort(): O(n log n) Timsort
For frequent front inserts use collections.deque (O(1) both ends). For frequent membership tests use a set (O(1)).
Q2. What is the difference between list.sort() and sorted()?Reveal
Answer: list.sort() sorts in-place, returns None, only works on lists. sorted(iterable) returns a new sorted list, works on any iterable. Use sort() to modify the list; sorted() to preserve the original or to sort non-list iterables. Both accept key and reverse parameters.
Q3. What is the difference between append() and extend()?Reveal
Answer: append(x) adds x as a single element. extend(iterable) unpacks and adds each item. lst.append([1,2]) gives [..., [1,2]] (nested). lst.extend([1,2]) gives [..., 1, 2]. The += operator calls extend. Common bug: using append when extend was intended, creating a list of lists.

Dictionaries & dict Methods
Data Structures⌄
📖 Explanation

Dicts are mutable, ordered (Python 3.7+) hash maps. Keys must be hashable. Lookup, insert, and delete are O(1) average. Python 3.9+ adds the merge operator | and update-in-place |=. Key patterns: get(k, default) avoids KeyError, setdefault initialises missing keys, defaultdict auto-creates values, Counter for frequency counting.

Interview Questions
Q1. What is the time complexity of dict operations?Reveal
Answer: Average case: lookup, insert, delete all O(1) — CPython uses a hash table. Worst case O(n) with many hash collisions (very rare with good hash functions). Iteration O(n). Only hashable (immutable) objects can be keys: ints, strings, tuples (if contents are hashable). Lists and dicts cannot be keys.
Q2. What is the difference between d[key] and d.get(key)?Reveal
Answer: d[key] raises KeyError if missing. d.get(key) returns None (or a specified default: d.get(key, default)). Use d[key] when the key must exist (missing = programming error). Use get() when absence is expected and you want to handle it gracefully without try/except.
Q3. What is the difference between defaultdict and setdefault()?Reveal
Answer: defaultdict(factory) auto-creates missing keys on every access using the factory. setdefault(key, default) only sets on explicit call. defaultdict is cleaner for building nested structures (adjacency lists, grouping). setdefault is better for one-off conditional initialisation. Neither raises KeyError for missing keys when used correctly.

Tuples, NamedTuples & dataclasses
Data Structures⌄
📖 Explanation

Tuples are immutable, ordered sequences. Less memory than lists; hashable (can be dict keys/set members) if all elements are hashable. Used for: multiple return values, records, coordinates, heterogeneous data groups. The trailing comma creates single-element tuples: (42,) — (42) is just int.

Interview Questions
Q1. When should you use a tuple instead of a list?Reveal
Answer: Use tuples for: (1) multiple return values (semantic signal that values belong together), (2) immutable records — coordinates, RGB, database rows, (3) dict keys (tuples are hashable; lists aren't), (4) slight performance win (smaller, faster). Use lists when you need to modify elements. As a rule of thumb: tuples for heterogeneous data with fixed structure; lists for homogeneous sequences you'll modify.
Q2. What is the difference between namedtuple and dataclass?Reveal
Answer: namedtuple: immutable, lightweight (no overhead vs tuple), iterable/unpackable, inherits all tuple methods. dataclass: mutable by default (use frozen=True for immutability), richer features (__post_init__, field(), ClassVar), doesn't behave like a tuple. Use namedtuple for lightweight immutable records. Use dataclass for mutable objects with methods, defaults, and post-init logic.
Q3. Why does (42) not create a tuple but (42,) does?Reveal
Answer: Parentheses in Python group expressions, not create tuples. (42) is the integer 42 in parentheses. A tuple is created by the comma, not the parentheses. (42,) — the trailing comma makes it a tuple. 42, (no parentheses) also creates a tuple. This trips people up in return (value) — returns int, not tuple.

Interview Questions
Q1. What is the time complexity of 'in' for sets vs lists?Reveal
Answer: x in set: O(1) average (hash lookup). x in list: O(n) linear scan. For frequent membership tests, always convert to a set: valid = set(valid_values); if user_input in valid: .... This matters enormously at scale: 1 million items — list takes ~1M comparisons; set takes 1.
Q2. How do you deduplicate a list while preserving order?Reveal
Answer: list(dict.fromkeys(lst)) — dict preserves insertion order (Python 3.7+) and deduplicates keys inherently. O(n) and order-preserving. list(set(lst)) deduplicates but does NOT preserve order. The dict.fromkeys trick is the idiomatic Python solution.
Q3. When would you use frozenset?Reveal
Answer: When you need a set to be (1) a dict key (frozensets are hashable; sets are not), (2) a member inside another set, or (3) immutable to prevent accidental modification. Classic use: representing undirected graph edges as frozenset({a, b}) as dict keys so direction doesn't matter.

Comprehensions & Generators
Data Structures⌄
📖 Explanation

Comprehensions: list [...], set {...}, dict {k:v ...}, generator (...). All support if filter and nested for clauses. Generator expressions are lazy — they compute one value at a time, using O(1) memory regardless of size. Generator functions use yield to produce values on demand; yield from delegates to a sub-iterator.

itertools provides fast, memory-efficient combinatoric and infinite iterators: chain, islice, takewhile, dropwhile, groupby, product, combinations, permutations, count, cycle, repeat, starmap, zip_longest, accumulate.

[x for x in it if cond] — list; eager; O(n) memory
(x for x in it if cond) — generator; lazy; O(1) memory
yield — turns function into generator; suspends on each yield
yield from iterable — delegate to sub-iterator; cleaner recursion
next(gen, default) — advance generator; default prevents StopIteration
itertools — chain/islice/groupby/product/combinations/permutations/count

Interview Questions
Q1. What is the difference between a list comprehension and a generator expression?Reveal
Answer: List comp [...] computes all values immediately — O(n) memory. Generator (...) is lazy — one value at a time, O(1) memory. Use generators for: large datasets, pipeline processing, passing to sum/any/all without intermediate storage. Interview Questions
Q1. What is CPython bytecode and how do you inspect it?Reveal
Answer: CPython compiles Python source to bytecode — a low-level set of instructions for the CPython VM. Stored in .pyc files in __pycache__. Use dis.dis(fn) to see the bytecode for a function. This is useful for understanding why two implementations differ in speed, debugging surprising behaviour, and learning how Python executes your code. Notable: function calls (CALL_FUNCTION) are expensive; attribute lookups (LOAD_ATTR) are slower than local vars (LOAD_FAST).
Q2. Why does 'is' sometimes return True for identical strings?Reveal
Answer: CPython interns strings that look like identifiers (letters, digits, underscores) as an optimisation — these strings are stored once and reused. So 'hello' is 'hello' may be True. Non-identifier strings (with spaces, special chars) are generally not interned: 'hello world' is 'hello world' is often False. Never rely on this — it's an implementation detail. Always use == for string comparison.
Q3. What are fast locals and why are local variables faster than globals?Reveal
Answer: Python functions store local variables in a fixed-size C array indexed at compile time. Accessing a local is LOAD_FAST — array index lookup, O(1), very fast. Global variables are stored in a dict and accessed with LOAD_GLOBAL — dict hash lookup, slightly slower. This is why it's a micro-optimisation to copy a frequently used global into a local inside a tight loop: local_fn = global_fn.
