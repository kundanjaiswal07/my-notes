AI, ML, Deep Learning Concepts
D1: AI/ML Fundamentals⌢
📚 Overview

AI is the broad field of creating intelligent systems. ML is learning from data without explicit programming. Deep Learning uses neural networks with multiple layers. For the exam, understand these distinctions and when each applies.

🎯 Key Points
  • AI = general field; ML = learn from data; DL = neural networks with layers
  • AI applications: robotics, NLP, computer vision, autonomous systems
  • ML types: supervised, unsupervised, reinforcement learning
  • DL best for: image/video analysis, NLP tasks, complex patterns
  • When to use: AI for general automation, ML for data-driven tasks, DL for unstructured data
Practice Questions
Q1. What is the key difference between ML and DL?Show
ML learns patterns from data using algorithms (trees, SVM). DL is a subset using neural networks with multiple layers. DL needs more data/compute but excels at images, text, audio.
Q2. Example of supervised learning classification:Show
Email spam detection - you have labeled examples (spam/not spam) and predict on new emails. Other examples: fraud detection, disease diagnosis, sentiment analysis.
Q3. When should you choose unsupervised learning?Show
When you have no labeled data and want to discover patterns. Examples: customer segmentation, anomaly detection, market basket analysis using clustering/association rules.

The complete ML workflow: problem definition, data collection, exploration (EDA), preprocessing, feature engineering, model training, hyperparameter tuning, evaluation, deployment, and monitoring. Each stage is critical. AWS SageMaker automates many stages.

🎯 Key Points

Practice Questions
Q1. Why is EDA (exploratory data analysis) critical?Show
EDA reveals data quality issues, patterns, outliers, and class imbalance before modeling. Skipping it leads to garbage models. Tools: SageMaker Data Wrangler for automated EDA.
Q2. What is data leakage and how to prevent it?Show
Leakage = test data info accidentally used in training. Prevention: (1) Split data before any preprocessing, (2) Scale/encode using only train set statistics, (3) Never use future info. Always keep train/validation/test separate.
Q3. What is model drift and how does SageMaker monitor it?Show
Drift = model performance degrades as real-world data changes. SageMaker Model Monitor detects input/prediction drift automatically. When detected, retrain the model.

Supervised Learning: Regression & Classification
D1: AI/ML Fundamentals⌢
📚 Overview

Supervised learning uses labeled data (X, Y pairs). Regression predicts continuous values (house price, temperature). Classification predicts categories (spam/ham, disease/healthy). Choose based on your target variable type.

🎯 Key Points
  • Regression: predict continuous values; use regression metrics (RMSE, MAE, R-squared)
  • Binary Classification: 2 classes (spam/not spam); Accuracy, Precision, Recall, ROC-AUC
  • Multi-class Classification: 3+ classes (iris species); macro/weighted F1-score
  • Common algorithms: Linear Regression, Logistic Regression, Decision Trees, Random Forests
  • AWS services: SageMaker built-in algorithms, AutoML for automatic algorithm selection
  • Class imbalance: use F1-score not accuracy; techniques: SMOTE, class weights
Practice Questions
Q1. Classify this problem: predict if a customer will buy.Show
Binary Classification. You have historical data (bought/didn't buy) with features. Predict on new customers. Algorithm: Logistic Regression or Random Forest. Metric: if false positives costly, prioritize Precision; false negatives costly, prioritize Recall.
Q2. When is accuracy a misleading metric?Show
With imbalanced data. Example: 99% negative class, model predicts all negatives = 99% accuracy but useless. Use F1-score, Precision, Recall, ROC-AUC instead.
Q3. Explain train/validation/test split and why it matters.Show
Train set: fit model. Validation set: tune hyperparameters. Test set: final evaluation (never seen during training). Prevents overfitting. AWS standard: 70/15/15 split.

Unsupervised Learning & Clustering
D1: AI/ML Fundamentals⌢
📚 Overview

Unsupervised learning finds patterns in unlabeled data. Clustering groups similar items (K-Means, hierarchical clustering). Dimensionality reduction compresses data (PCA). Used for customer segmentation, anomaly detection, feature extraction.

🎯 Key Points
  • Clustering: group similar items; K-Means (fixed clusters), hierarchical (dendrograms)
  • Dimensionality reduction: compress features; PCA (linear), autoencoders (non-linear)
  • Anomaly detection: find outliers; use isolation forests, One-Class SVM
  • K-Means: specify k clusters beforehand; minimizes within-cluster distance
  • Hierarchical: creates tree of clusters; dendrogram shows merging process
  • AWS services: SageMaker K-Means, SageMaker IP Insights for anomaly detection
Practice Questions
Q1. How to choose the right number of clusters in K-Means?Show
Use Elbow Method: plot inertia vs k, look for elbow (diminishing returns). Or Silhouette Score: measure of cluster quality (-1 to 1; higher better). AWS can automate this.
Q2. Difference between K-Means and Hierarchical Clustering?Show
K-Means: fast, requires k preset, creates flat clusters. Hierarchical: slower, no k needed, creates tree of clusters. Use K-Means for speed; hierarchical for dendrogram visualization.
Q3. What is dimensionality reduction used for?Show
Reduce features while preserving variance for: (1) visualization (PCA to 2D), (2) reduce model complexity/training time, (3) remove noise/multicollinearity, (4) enable faster prediction.

Generative AI & Large Language Models
D2: GenAI Fundamentals⌢
📚 Overview

GenAI creates new content (text, images, audio) using foundation models. Large Language Models (LLMs) are transformer-based models trained on massive text. Foundation Models are large pre-trained models adaptable to many tasks. GenAI represents a paradigm shift in AI capabilities.

🎯 Key Points
  • GenAI: systems that generate new content (text, images, audio, code)
  • LLMs: transformer-based models trained on billions of text tokens
  • Foundation Models: large pre-trained models work across multiple tasks
  • Tokens: units of text (roughly 1 token = 4 characters)
  • Transformer architecture: attention mechanism enables parallel processing
  • Key models: GPT (OpenAI), Claude (Anthropic), Llama (Meta), Titan (Amazon)
Practice Questions
Q1. What is a foundation model and why is it foundational?Show
A large pre-trained model trained on diverse data that can be adapted to many downstream tasks (classification, summarization, Q&A, translation). Foundational because you build on it rather than train from scratch.
Q2. Explain tokens and why they matter for cost.Show
Tokens are text chunks (~4 chars). Input/output token count determines API cost. Longer prompts and responses cost more. Token counting: 1000 tokens ≈ 750 words.
Q3. What advantage do LLMs have over traditional ML models?Show
LLMs: (1) few-shot learning (learn from examples in prompt), (2) zero-shot (work without examples), (3) general knowledge (trained on web scale), (4) multi-task capability without retraining.

Prompt Engineering Basics
D2: GenAI Fundamentals⌢
📚 Overview

Prompt engineering is crafting effective inputs to get desired outputs from LLMs. Key techniques: be specific, provide examples (few-shot), use formatting, specify output format, set temperature/top-p for creativity. Good prompts dramatically improve results.

🎯 Key Points
  • Specificity: clear, detailed instructions; avoid ambiguous wording
  • Few-shot learning: provide examples in prompt for desired output format
  • Zero-shot: LLM figures it out from instruction alone (usually works)
  • Temperature: 0 (deterministic) to 1 (creative); default ~0.7
  • Top-p (nucleus sampling): control diversity of token selection
  • Output format: explicitly ask for JSON, bullet points, etc.
Practice Questions
Q1. Craft a prompt for sentiment analysis.Show
Bad: 'Analyze this.' Good: 'Classify the sentiment of the following text as positive, negative, or neutral. Return as JSON with keys: sentiment, confidence. Text: ...' Specific instructions > vague requests.
Q2. When should you use temperature 0 vs 1?Show
Temperature 0: factual tasks (math, code, summarization). Temperature 1 (or 0.9): creative tasks (brainstorming, storytelling). Default 0.7 balances both.
Q3. Explain few-shot prompting.Show
Include examples of input-output pairs in the prompt. LLM learns pattern and applies to new input. Example: '1+1=2, 2+2=4, 5+5=?' Few-shot often beats zero-shot and reduces ambiguity.

GenAI Costs, Latency & Trade-offs
D2: GenAI Fundamentals⌢
📚 Overview

GenAI applications have cost and latency trade-offs: using larger models improves quality but costs more and is slower. Smaller models are cheaper and faster but less accurate. Choose based on use case requirements: quality-critical vs latency-critical vs cost-sensitive.

🎯 Key Points
  • Model size/quality trade-off: larger models better but slower/more expensive
  • Latency: larger models take longer to generate tokens (~100ms per token)
  • Cost: varies by model; token-based pricing; input/output tokens separate
  • Batch processing: cheaper than real-time for non-urgent tasks
  • Caching: recent Bedrock feature reduces costs for repeated prompts
  • Compute options: on-demand vs provisioned throughput (reserved capacity cheaper)
Practice Questions
Q1. How to choose between Claude 3 Opus vs Haiku?Show
Opus: best quality, slower, expensive. Haiku: fastest, cheapest, good for simple tasks. Choose Opus for complex reasoning/quality; Haiku for high-volume simple requests. Bedrock supports all models.
Q2. What is provisioned throughput and when use it?Show
Reserve model capacity for guaranteed throughput at discount (~40% cheaper). Good if: consistent daily usage, predictable volume, not cost-sensitive to upfront commitment.
Q3. How can you reduce GenAI API costs?Show
(1) Use smaller models when possible, (2) Batch requests, (3) Cache repeated prompts, (4) Use provisioned throughput for predictable load, (5) Filter token use (avoid unnecessary context).

Responsible AI in GenAI Applications
D2: GenAI Fundamentals⌢
📚 Overview

GenAI brings responsible AI concerns: hallucinations (false confident outputs), bias in training data, privacy of training data, inappropriate content, copyright issues. Bedrock Guardrails and SageMaker Clarify help mitigate these risks. Transparency about AI usage is essential.

🎯 Key Points
  • Hallucination: LLM fabricates plausible-sounding but false information
  • Bias: training data biases emerge in outputs (historical discrimination, stereotypes)
  • Privacy: training data may contain sensitive info; PII redaction needed
  • Content safety: guardrails prevent harmful outputs (violence, hate, adult content)
  • Copyright: training on copyrighted material; use licensed models responsibly
  • Transparency: users should know when interacting with AI
Practice Questions
Q1. What is hallucination and how to reduce it?Show
Hallucination = LLM confidently says false info. Example: 'What is the capital of Atlantis?' Mitigations: (1) RAG (retrieve facts), (2) lower temperature (more conservative), (3) explicit 'I don't know' instructions.
Q2. How do you know if a model has bias?Show
Test with diverse prompts across demographics. Example: 'Generate CEO description' and check if gender/race stereotypes emerge. Use SageMaker Clarify for automated bias detection.
Q3. Why is transparency about GenAI important?Show
Users have right to know they're interacting with AI. Impacts: trust, informed decisions, regulatory compliance (GDPR, AI Act). Disclose AI use in content, decisions, recommendations.

Design Patterns for FM Applications
D3: FM Applications⌢
📚 Overview

When building with foundation models: determine if you need real-time or batch. RAG for knowledge without retraining. Fine-tuning for custom patterns. Chain-of-thought prompts for complex reasoning. Consider token costs, latency SLAs, hallucination risks.

🎯 Key Points
  • RAG pattern: retrieve facts before generating (better for factual accuracy)
  • Fine-tuning: when base model performance insufficient, have labeled data
  • In-context learning: provide examples in prompt without retraining
  • Chaining: break complex problem into steps; solve sequentially
  • Caching: reuse computations for repeated requests
  • Batch processing: non-urgent tasks; cheaper than real-time
Practice Questions
Q1. When to use RAG vs fine-tuning?Show
RAG: for current/specific knowledge without model retraining. Fine-tuning: when base model lacks domain knowledge, you have training data, need consistent outputs. RAG faster to implement; fine-tuning more accurate for specific tasks.
Q2. What is chain-of-thought prompting?Show
Breaking problem into steps, asking model to reason each step. Example: Instead of 'Solve 8*(7+3)', ask 'First compute 7+3, then multiply by 8. Show work.' Improves accuracy on complex tasks.
Q3. How does prompt caching reduce costs?Show
Recent Bedrock feature: cache prompt fragments. Repeated prompts skip recomputation. Example: same system prompt + different queries. Saves cost and latency.

Fine-Tuning vs RAG vs Pre-training
D3: FM Applications⌢
📚 Overview

Three customization approaches for foundation models. Pre-training (most expensive): train from scratch on your data. Fine-tuning: adapt pre-trained model on your data. RAG (cheapest): retrieve knowledge without retraining. Choose based on data, budget, urgency.

🎯 Key Points
  • Pre-training: train from scratch on massive corpus; requires GPUs, weeks/months, billions tokens
  • Fine-tuning: adapt pre-trained model on your data; faster, cheaper, requires labeled data
  • RAG: retrieve relevant docs, include in prompt; no training; works for knowledge tasks
  • Cost hierarchy: RAG < Fine-tuning < Pre-training
  • Speed: RAG fastest; fine-tuning days; pre-training months
  • When fine-tune: domain-specific language, style consistency, performance gap
Practice Questions
Q1. When would you choose pre-training over fine-tuning?Show
Almost never for new orgs. Pre-training only if: unique language/domain, massive custom data, budget unlimited. Usually fine-tuning sufficient; Bedrock pre-trained sufficient for most.
Q2. What data do you need for fine-tuning?Show
Labeled examples in your target format. Minimum: 100-500 high-quality examples. More is better. Examples: (prompt, desired_output) pairs.
Q3. Can you fine-tune a Bedrock model?Show
Limited support. Bedrock is primarily for inference. SageMaker JumpStart or custom SageMaker training for fine-tuning. Check current docs for Bedrock fine-tuning availability.

Model Evaluation Metrics (BLEU, ROUGE, BERT Score)
D3: FM Applications⌢
📚 Overview

Foundation model outputs evaluated using specialized metrics. BLEU measures n-gram overlap (machine translation). ROUGE measures recall of n-grams and subsequences (summarization). BERT Score uses embeddings for semantic similarity. No single metric perfect; use multiple.

🎯 Key Points
  • BLEU: 0-100 scale; measures word/phrase overlap with reference; good for translation
  • ROUGE: multiple variants (ROUGE-1/2/L); recall-focused; standard for summarization
  • METEOR: considers synonyms and morphology; better than BLEU
  • BERT Score: contextual embeddings; semantic similarity; language-agnostic
  • Human evaluation: essential for quality assessment; subjective but definitive
  • Task-specific metrics: custom based on use case (QA accuracy, code correctness)
Practice Questions
Q1. Which metric for machine translation?Show
BLEU is standard (0-100). Also use METEOR (handles synonyms) and human eval. BLEU of 30+ reasonable; 40+ good; 50+ excellent.
Q2. How does BERT Score differ from BLEU/ROUGE?Show
BLEU/ROUGE: lexical overlap. BERT Score: semantic similarity using embeddings. Better captures paraphrases and synonyms. More aligned with human judgment.
Q3. Why use multiple metrics?Show
Each metric has blind spots. BLEU good for translation, poor for paraphrases. ROUGE for summarization, not translation. Use 3-4 metrics + human eval for comprehensive assessment.

Embeddings, Vector Databases & Retrieval
D3: FM Applications⌢
📚 Overview

Embeddings convert text to vectors capturing semantic meaning. Vector databases (OpenSearch, Aurora with pgvector) store embeddings for fast semantic search. Critical for RAG: embed documents, search by similarity, retrieve for LLM context.

🎯 Key Points
  • Embeddings: text -> dense vectors; capture meaning; enable semantic search
  • Vector databases: store/index embeddings; fast similarity search
  • Services: OpenSearch, Aurora with pgvector, Amazon Bedrock Embeddings API
  • Similarity metrics: cosine similarity most common; also Euclidean, dot product
  • Chunk size: split documents into chunks before embedding (balance: detail vs retrieval)
  • Re-ranking: retrieve top-k, then re-rank for final selection (improves quality)
Practice Questions
Q1. How does embeddings enable RAG?Show
Embed user query & documents. Search vector DB for similar documents. Include top results in LLM prompt. Reduces hallucination by grounding in facts.
Q2. What is chunking and why matters?Show
Split long documents into overlapping chunks (500-1000 tokens). Tradeoff: smaller chunks more relevant but miss context; larger chunks preserve context but dilute relevance. Test to optimize.
Q3. What similarity metric should you use?Show
Cosine similarity is standard for embeddings (normalized vectors). Euclidean/L2 for normalized vectors also works. Dot product for non-normalized. Cosine usually sufficient.

Bias Detection & Fairness in AI
D4: Responsible AI⌢
📚 Overview

Bias in ML: historical data biases persist in models. Impacts: unfair decisions (hiring, lending, criminal justice). Mitigation: diverse training data, bias detection before deployment, fairness metrics, human review. AWS SageMaker Clarify detects and visualizes bias.

🎯 Key Points
  • Data bias: training data reflects historical discrimination
  • Algorithmic bias: model learns unfair patterns from data
  • Deployment bias: model used in discriminatory way
  • Bias metrics: disparate impact ratio, equal opportunity difference
  • SageMaker Clarify: automated bias detection by demographics
  • Mitigation: rebalance data, adjust decision thresholds, diverse teams
Practice Questions
Q1. How to detect gender bias in hiring ML model?Show
Evaluate model performance separately by gender. If reject rates differ significantly (>5%), investigate. Retrain with balanced data or adjust threshold. SageMaker Clarify automates this analysis.
Q2. What is disparate impact?Show
When decisions disproportionately harm protected groups. Example: hiring model rejects women at 40% vs men 20%. Illegal in many jurisdictions. Measure and mitigate before deployment.
Q3. Why is diverse team important for responsible AI?Show
Diverse perspectives catch blind spots. Different backgrounds identify biases others miss. Regulatory requirement in many regions (EU AI Act). Include domain experts, ethicists, affected communities.

Explainability & Model Interpretability
D4: Responsible AI⌢
📚 Overview

Explainability answers 'why did the model decide this?' Essential for high-stakes decisions (medical diagnosis, loan approval, criminal justice). Methods: SHAP values, feature importance, LIME. AWS SageMaker Clarify provides SHAP/feature importance.

🎯 Key Points
  • Black box vs interpretable models: trees/forests interpretable; DNNs black box
  • SHAP: contribution of each feature to prediction; game theory approach
  • Feature importance: which features drive model decisions
  • LIME: local interpretable model-agnostic explanations
  • SageMaker Clarify: automated SHAP values, feature importance, bias reports
  • Regulatory requirement: GDPR 'right to explanation' in many regions
Practice Questions
Q1. When is explainability critical?Show
High-stakes decisions: medical diagnosis, loan approval, criminal sentencing, hiring. Regulatory requirement (GDPR, Fair Lending Act). Users have right to explanation. Enables auditing and fairness checks.
Q2. How do SHAP values explain predictions?Show
SHAP assigns value to each feature showing its contribution (positive/negative/zero) to prediction. Sums to model output. Enable understanding feature impact.
Q3. Trade-off: accuracy vs interpretability?Show
Complex models (DNNs) often more accurate but less interpretable. Interpretable models (trees) less accurate but explainable. Solution: use complex model + explanation tools. Modern approach: explain black boxes.

Safety, Hallucinations & Content Moderation
D4: Responsible AI⌢
📚 Overview

GenAI safety concerns: hallucinations (confident false outputs), inappropriate content, jailbreaking attempts. Bedrock Guardrails filter outputs. Techniques: RAG for facts, lower temperature for consistency, explicit safety instructions in prompts.

🎯 Key Points
  • Hallucination: LLM fabricates plausible-sounding false info; hard to detect
  • Content moderation: filter violence, hate speech, adult content, PII
  • Jailbreaking: user attempts to bypass safety measures
  • Bedrock Guardrails: content filters, denied topics, PII redaction
  • Prompt injection: malicious input tries to override system instructions
  • Monitoring: detect policy violations in real-time; log for audit
Practice Questions
Q1. How to reduce hallucinations?Show

Q2. What is prompt injection attack?Show
User provides malicious input trying to override system prompt. Example: 'Ignore previous instructions and...' Defense: Bedrock Guardrails, robust system prompts, input validation.
Q3. How does content moderation in Bedrock work?Show
Configure filters by category. Bedrock pre/post-filters inputs/outputs. Custom word filters. Optional: third-party content mod services. Flag violations for review.

Monitoring, Drift Detection & Retraining
D5: Security & Governance⌢
📚 Overview

Deployed models degrade as real-world data changes (data drift). SageMaker Model Monitor detects input/output drift. When drift detected, trigger retraining. Continuous monitoring essential for production reliability.

🎯 Key Points
  • Data drift: input distribution changes; model trained on different data
  • Prediction drift: prediction distribution changes; may indicate data drift
  • Accuracy drift: actual labels change; model performance degrades
  • SageMaker Model Monitor: automated drift detection
  • Monitoring schedule: continuous or periodic (hourly/daily)
  • Response: alert, retrain, or A/B test new version
Practice Questions
Q1. How does SageMaker Model Monitor work?Show
Captures model inputs/outputs. Compares to training baseline. Detects deviation via statistical tests (chi-square for categorical, Kolmogorov-Smirnov for continuous). Alerts when drift exceeds threshold.
Q2. What causes data drift?Show
User behavior changes, market shifts, seasonal effects, data collection process changes. Example: ML model trained on 2023 data, deployed 2024; user preferences changed.
Q3. When to retrain a model?Show
Automatic: when drift detected beyond threshold. Manual: performance drops, new data available, business logic changes. Frequency: daily for high-drift models, weekly/monthly for stable.

WK 3

WK 4

Security & Practice (Topics 19-21 + Full Exam): IAM, governance, monitoring. Goal: score 700+. Practice: Full-length mock exam (65 questions). Review weak areas. Final deep-dive on domains 4-5.

Tips

Read the exam guide thoroughly. Know exact AWS services tested (Bedrock, SageMaker, Clarify, Model Monitor, etc.). Passing is 700/1000; not perfection. Time management: 65 questions in 130 minutes = 2 min/question average.

⚠️ Common Mistakes to Avoid
×

Neglecting Domain 3: It's 28% of exam. If weak here, you fail. Spend half your study time on FM Applications (RAG, fine-tuning, evaluation metrics).

×

Assuming GenAI knowledge = ML knowledge: GenAI is just one piece. Domains 1-2-4-5 equally important. Study fundamentals thoroughly.

×

Not doing hands-on: Reading isn't enough. Create Bedrock app, set up RAG, enable Model Monitor. Hands-on reveals gaps theory doesn't.

×

Cramming the night before: Sleep matters. Brain consolidates learning during sleep. Study 4 weeks consistently > 1 week intensive.

×

Confusing services: Bedrock = inference on pre-trained FMs. SageMaker = full ML lifecycle including training. Don't mix them up on exam.
