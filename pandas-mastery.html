What is Pandas & Core Data Structures
Basics⌄
📖 Explanation

Pandas gives you two structures built on NumPy: Series (1D labelled array) and DataFrame (2D table of Series sharing an index). The Index enables fast lookups, auto-alignment during arithmetic, and time-series ops. dtypes control memory: int64, float64, object (strings — expensive), bool, datetime64, and category (low-cardinality strings — 90% memory saving).

Series — 1D; s['label'] or s[0]
DataFrame — 2D; df['col'] returns Series; df[['a','b']] returns DataFrame
Index — immutable labels; default RangeIndex (0,1,2…)
dtypes — int64, float64, object, bool, datetime64[ns], category
import pandas as pd s = pd.Series([10,20,30], index=['a','b','c']) s['b'] # 20 df = pd.DataFrame({'name':['Alice','Bob'], 'age':[25,30]}) df.dtypes # name: object, age: int64 df.shape # (2, 2) df['age'] # returns a Series df[['name','age']] # double brackets = DataFrame
Interview Questions
Q1. Difference between Series and DataFrame? Can you convert between them?Reveal
Answer: Series is 1D (one column + index); DataFrame is 2D (multiple Series sharing an index). Convert: s.to_frame() (Series→DataFrame), df['col'] (DataFrame column→Series). Key insight: a DataFrame is essentially a dict of Series objects.
Q2. Why is the default RangeIndex important?Reveal
Answer: It enables .loc[] lookups, auto-aligns data during arithmetic, and powers time-series ops (DatetimeIndex). Mismatched indexes after a reset silently introduce NaN in joins.
Q3. Why is 'object' dtype inefficient for strings?Reveal
Answer: Stores Python object pointers — each string is a separate heap allocation. Use astype('category') for low-cardinality columns (city, gender) — cuts memory up to 90% by storing integer codes internally.

Reading & Writing Data
Basics⌄
📖 Explanation

read_csv() is the most-used Pandas function. The professional parameters: usecols loads only needed columns; dtype avoids wrong type inference; parse_dates auto-converts date strings; chunksize processes files larger than RAM by returning an iterator of smaller DataFrames. Always write with index=False to avoid the mysterious Unnamed: 0 column. Prefer Parquet for large data — 3–10x smaller and much faster.

usecols + dtype — load only what you need; specify types upfront
chunksize — iterate huge files without loading all into RAM
to_csv(index=False) — always; omitting creates Unnamed:0 on re-read
read_parquet / to_parquet — columnar, compressed, dtype-preserving
# Only needed columns + correct types df = pd.read_csv('data.csv', usecols=['date','sales'], dtype={'sales':'float32'}, parse_dates=['date']) # 10 GB file — process in chunks results = [] for chunk in pd.read_csv('big.csv', chunksize=50000): results.append(chunk[chunk['sales'] > 0]) df = pd.concat(results, ignore_index=True) df.to_csv('out.csv', index=False) # critical! df.to_parquet('out.parquet') # 5-10x faster/smaller
Interview Questions
Q1. How do you read only specific columns from a 10 GB CSV without OOM errors?Reveal
Answer: Two approaches: (1) usecols=['a','b'] — reads only those columns at OS level, ignoring the rest. (2) chunksize=100000 — iterate, filter/aggregate, concat results. Best: combine both plus dtype spec for maximum efficiency.
Q2. Why does to_csv() sometimes produce 'Unnamed: 0' when re-read?Reveal
Answer: Without index=False, Pandas writes the row index (0,1,2…) as the first column. On re-read it appears as Unnamed: 0. Fix: always write with df.to_csv('f.csv', index=False).
Q3. When would you use Parquet over CSV?Reveal
Answer: Use Parquet when: data is accessed repeatedly, file is >100MB, or dtypes must be preserved (CSV loses them on re-read). Parquet is columnar — reads only requested columns, 3–10x smaller, 5–20x faster. Use CSV for one-time loads or sharing with non-Python tools.

Exploring DataFrames (EDA)
Basics⌄
📖 Explanation

Good EDA follows a fixed sequence. info() shows dtypes + non-null counts — call it first. describe() gives stats for numerics; if mean differs greatly from 50th percentile, the column is skewed. value_counts(normalize=True) shows category proportions. isnull().mean()*100 gives % missing per column — sort descending to see worst offenders. Always check duplicated().sum() — duplicate rows silently inflate aggregates.

info() — dtypes + non-null counts + memory; always first
describe(include='all') — numeric stats + string top/freq
isnull().mean()*100 — % missing; sort to see worst columns
value_counts(normalize=True) — proportional frequency
duplicated().sum() — always check for silent duplicates
df.shape df.info() # dtypes + nulls df.describe(include='all') # full stats (df.isnull().mean() * 100).sort_values(ascending=False) df['city'].value_counts(normalize=True) # proportions df.duplicated().sum() # duplicate rows df.nunique() # distinct values per col df.memory_usage(deep=True).sum() / 1024**2 # MB
Interview Questions
Q1. Walk me through your first 5 EDA lines on a new dataset.Reveal
Answer: df.shape (size), df.info() (dtypes + nulls), df.describe(include='all') (outliers, constant cols), df.isnull().sum() (missing), df.duplicated().sum() (duplicate rows). Then value_counts for categoricals and distribution plots for numerics.
Q2. What's the difference between df.info() and df.describe()?Reveal
Answer: info() is structural — dtypes, non-null counts, memory. Use it to spot wrong types and missing data. describe() is statistical — mean, std, percentiles for numerics. A large gap between mean and median (50%) signals outliers or skew.
Q3. How do you find % of missing values per column?Reveal
Answer: (df.isnull().sum() / len(df) * 100).sort_values(ascending=False). isnull() returns boolean (True=1), .sum() counts them, dividing by row count gives proportion, *100 gives percent. Sorting shows worst columns first.

Indexing & Selection (.loc / .iloc)
Basics⌄
📖 Explanation

.loc is label-based — uses the actual index labels. Its slices are inclusive on both ends: df.loc[0:3] gives 4 rows (0,1,2,3). .iloc is position-based — uses integer positions like Python lists; slices are exclusive on the right: df.iloc[0:3] gives 3 rows (0,1,2). Boolean masking filters rows by condition — use & (not and), | (not or), ~ (not), each condition in parentheses.

.loc[row_label, col_label] — label-based; inclusive slice
.iloc[row_int, col_int] — position-based; exclusive on right
.at/.iat — single-cell access; fastest
Boolean mask — & | ~ with parentheses; never use Python 'and'/'or'
# .loc — LABELS, inclusive both ends df.loc[0:3] # rows 0,1,2,3 (4 rows!) df.loc[0:3, 'name':'age'] # rows 0-3, cols name→age df.loc[df['age']>25, 'name'] # filter rows + pick col # .iloc — POSITIONS, exclusive on right df.iloc[0:3] # rows 0,1,2 (3 rows!) df.iloc[-1] # last row # Boolean masking — parentheses required! df[(df['age'] > 25) & (df['city'] == 'Mumbai')] df[~df['city'].isin(['Delhi'])] # NOT in list
Interview Questions
Q1. Difference between .loc and .iloc? When does one fail?Reveal
Answer: .loc uses labels (inclusive slice); .iloc uses positions (exclusive right, like Python list). When .loc fails: if index is strings ['a','b','c'], df.loc[0] raises KeyError — use df.iloc[0]. Slicing gotcha: df.loc[0:3] = 4 rows; df.iloc[0:3] = 3 rows.
Q2. Why must you use & instead of 'and' in boolean filtering?Reveal
Answer: Python's and expects a single scalar bool. A Pandas Series is not a scalar — using and raises ValueError: The truth value of a Series is ambiguous. Use & (bitwise AND, element-wise). Also wrap each condition in parentheses: (df['a']>5) & (df['b']=='x').
Q3. What is SettingWithCopyWarning and how do you fix it?Reveal
Answer: Triggered by chained indexing: df[df['age']>25]['name'] = 'x' — Pandas isn't sure if the slice is a view or copy, so the assignment may silently not stick. Fix: use df.loc[df['age']>25, 'name'] = 'x'. For read operations, call .copy() on the slice to be explicit.

Handling Missing Data
Core ops⌄
📖 Explanation

Real datasets always have NaN. They propagate silently: NaN + 5 = NaN. dropna() removes rows/cols: how='any' drops if any cell is NaN, how='all' only if every cell is NaN, thresh=n keeps rows with at least n valid values. fillna() replaces NaN with a scalar, per-column dict, ffill (carry last valid forward), or bfill. For time series, ffill is the standard approach.

isnull().sum() — count NaN per col; .mean()*100 gives %
dropna(how, thresh, subset) — remove rows/cols with NaN
fillna(value / method) — scalar, dict, ffill, bfill
interpolate() — estimate values between known points (time series)
df.isnull().sum() # count per col df.dropna() # drop if ANY col NaN df.dropna(how='all') # drop only if ALL NaN df.dropna(subset=['age'], thresh=3) # custom logic df['age'].fillna(df['age'].median()) # fill with median df.fillna({'age':0, 'city':'Unknown'}) # per-column df.fillna(method='ffill') # forward fill df['temp'].interpolate(method='linear')# smooth gaps
Interview Questions
Q1. Difference between dropna(how='any') and dropna(thresh=n)?Reveal
Answer: how='any' drops a row if at least 1 value is NaN — aggressive. how='all' drops only if every value is NaN — lenient. thresh=n keeps a row only if it has at least n non-NaN values — granular control. Example: a row with 4 good values and 1 NaN: how='any' drops it, thresh=3 keeps it.
Q2. When to use ffill vs fillna(mean)?Reveal
Answer: ffill is for time series where the last known value is still valid (stock price, sensor reading, daily log). fillna(mean) is for independent random missing values where no temporal relationship exists. Use fillna(median) instead of mean when the column has outliers — median is robust to skew.
Q3. How do NaN values affect sum() and mean()?Reveal
Answer: Pandas skips NaN by default (skipna=True). sum() treats NaN as 0; mean() divides by count of non-NaN values. To force NaN propagation: col.mean(skipna=False). Note: count() counts non-NaN; len(df) counts all rows — use count() for data quality checks.

Filtering & Querying
Core ops⌄
📖 Explanation

Boolean masking creates a True/False Series used as a row selector. Combine conditions with & (AND), | (OR), ~ (NOT) — always wrap each condition in parentheses. query() writes the same filter as a readable string; it uses @var to inject Python variables and internally uses numexpr for faster execution on large DataFrames. isin() replaces long OR chains cleanly.

& | ~ with parentheses — Boolean mask; never use Python 'and'/'or'
query("expr") — string expression; @var injection; numexpr-backed
isin(list) — match any value in a list; ~ to negate
between(lo, hi) — inclusive range; str.contains(na=False) for strings
# Boolean mask df[(df['age'] > 25) & (df['city'] == 'Mumbai')] df[~df['city'].isin(['Delhi'])] # NOT in list # query() — cleaner syntax min_age = 25 df.query('age > @min_age and city == "Mumbai"') df[df['salary'].between(30000, 80000)] # inclusive df[df['name'].str.contains('kumar', case=False, na=False)]
Interview Questions
Q1. Advantage of query() over boolean masking?Reveal
Answer: Readability — 3+ conditions are much cleaner as a string. Performance — uses numexpr on large DataFrames (>200K rows), evaluating in C without intermediate arrays. Variable injection via @var. Limitation: column names with spaces need backticks: `first name` == 'x'.
Q2. How do you filter rows where a column's value is in a list?Reveal
Answer: df[df['city'].isin(['Mumbai','Delhi','Pune'])]. Much cleaner than OR chain. To exclude: df[~df['city'].isin(['Mumbai'])]. Can also do a semi-join: df[df['id'].isin(other_df['id'])] — keeps only rows whose id appears in another DataFrame.
Q3. What does na=False do in str.contains()?Reveal
Answer: By default, str.contains() returns NaN for rows where the column is NaN. Using that as a boolean filter raises ValueError. na=False treats NaN rows as "no match" (returns False), making the filter safe. Always use it: df[df['col'].str.contains('x', na=False)].

Adding, Renaming & Dropping
Core ops⌄
📖 Explanation

assign() adds new columns and returns a new DataFrame — perfect for method chaining. Use a lambda when the new column references another column you just created in the same chain. rename() accepts a dict of old→new names — surgical, only renames what you specify. Avoid inplace=True: it doesn't actually save memory, breaks chaining, and is being deprecated in Pandas 2.0+.

assign(col=expr) — returns new df; lambda references intermediate cols
rename(columns={'old':'new'}) — surgical; only specified cols renamed
df.columns = df.columns.str.lower().str.replace(' ','_') — clean all at once
drop(columns=['a']) — remove cols; prefer reassignment over inplace=True
# assign — chain-friendly df = (df .assign(bmi = df['weight'] / df['height']**2) .assign(category = lambda x: pd.cut(x['bmi'], bins=[0,18.5,25,999], labels=['under','normal','over'])) ) # rename columns df = df.rename(columns={'cust_id':'customer_id'}) # clean all column names in one line df.columns = df.columns.str.lower().str.replace(' ','_') df = df.drop(columns=['tmp'])
Interview Questions
Q1. inplace=True vs df = df.op() — which is better and why?Reveal
Answer: Prefer df = df.op(). Reasons: it's chainable (df.drop(...).rename(...).fillna(...)); inplace=True doesn't save memory (Pandas creates internal copies anyway); it returns None, breaking chains; and it's being deprecated in Pandas 2.0+.
Q2. How do you add a column that references another column just created in the same operation?Reveal
Answer: Use two chained assign() calls with a lambda. df.assign(tax=df['price']*0.18).assign(total=lambda x: x['price']+x['tax']). The lambda receives the DataFrame after the previous assign step, so 'tax' already exists when 'total' is computed.
Q3. How do you clean all column names (lowercase, underscores) in one line?Reveal
Answer: df.columns = df.columns.str.lower().str.strip().str.replace(' ', '_'). The Index object supports the same .str accessor as a Series. Very common when loading Excel files with inconsistent header formatting.

Sorting & Ranking
Core ops⌄
📖 Explanation

sort_values() sorts by one or more columns; pass a list of ascending booleans for multi-column sort. NaN values go last by default. rank() assigns numerical ranks with five methods for handling ties: average (mean of tied positions), min (lowest tied rank), max, first (appearance order), and dense (same rank, no gaps — most useful for leaderboards). nlargest(n, col) is faster than sort+head for top-N.

sort_values(by, ascending, na_position) — list for multi-column
rank(method='dense', ascending) — dense = tied items same rank, no gaps
groupby + rank — rank within groups (very common interview task)
nlargest(n) / nsmallest(n) — faster than sort + head
df.sort_values(['dept','salary'], ascending=[True,False], na_position='last') # dense: [100,90,90,80] → ranks [1,2,2,3] df['rank'] = df['score'].rank(method='dense', ascending=False) # Rank within group (top-3 per dept) df['dept_rank'] = df.groupby('dept')['salary'].rank( method='dense', ascending=False) df.nlargest(5, 'salary') # faster than sort+head
Interview Questions
Q1. Difference between rank(method='dense') and rank(method='average')?Reveal
Answer: For values [100,90,90,80]: average gives [1, 2.5, 2.5, 4] — tied items share the mean of their positions. dense gives [1, 2, 2, 3] — tied items share the same rank with no gaps. Use dense for leaderboards where you want position 3 to follow position 2 meaningfully.
Q2. How do you find the top-3 earner in each department?Reveal
Answer: df[df.groupby('dept')['salary'].rank(method='dense', ascending=False) <= 3]. The groupby+rank returns a Series of ranks relative to each department group. Filtering on rank <= 3 keeps the top 3 per group.
Q3. Why is nlargest() faster than sort_values().head()?Reveal
Answer: sort_values() fully sorts the array — O(n log n). nlargest(k) uses a partial heap sort — O(n log k) — finding only the top k without sorting everything else. For 1M rows and k=5, this is dramatically faster.

GroupBy & Aggregation
Core ops⌄
📖 Explanation

GroupBy follows split-apply-combine: split data into groups, apply a function, combine results. agg() reduces each group to one row (sum, mean, count). Use named agg syntax agg(alias=('col','func')) for clean flat column names. transform() is the key distinction — it returns a result with the same shape as the input, broadcasting group-level stats back to every row. filter() keeps/drops entire groups. apply() is the most flexible but slowest.

groupby(col).agg(name=('col','func')) — named agg; flat output names
transform() — same shape as input; broadcasts group stat to each row
filter(lambda x: cond) — keep groups where condition is True
as_index=False — keeps groupby col as regular column; skip reset_index()
# Named aggregation — flat column names summary = df.groupby('dept').agg( avg_sal = ('salary', 'mean'), headcount = ('id', 'count'), max_sal = ('salary', 'max') ).reset_index() # transform — broadcasts group stat to each row df['dept_avg'] = df.groupby('dept')['salary'].transform('mean') df['pct_of_avg'] = df['salary'] / df['dept_avg'] * 100 # filter — keep depts with avg salary > 60k df.groupby('dept').filter(lambda x: x['salary'].mean() > 60000)
Interview Questions
Q1. Difference between groupby agg() and transform()?Reveal
Answer: agg() reduces — one output row per group (loses original structure). transform() preserves shape — same number of rows as input, group result broadcast back. Use transform when you want to add a group statistic as a new column without losing original rows (e.g., 'salary as % of department average').
Q2. What does as_index=False do in groupby?Reveal
Answer: By default, the grouping column becomes the index of the result. as_index=False keeps it as a regular column — equivalent to .reset_index(). More convenient when you plan to merge the result back or save to CSV.
Q3. How do you apply multiple aggregation functions to multiple columns at once?Reveal
Answer: Named agg (preferred): df.groupby('dept').agg(avg_sal=('salary','mean'), max_sal=('salary','max'), med_age=('age','median')). Flat column names, no MultiIndex. The dict approach agg({'salary':['mean','max']}) produces MultiIndex columns that need flattening.

Merging & Joining
Core ops⌄
📖 Explanation

merge() is SQL-style join on key columns. inner keeps only matching rows; left keeps all left rows (NaN for unmatched right); outer keeps all from both. Duplicate keys cause row multiplication — 3 rows in df1 with key=5 and 2 in df2 gives 6 merged rows. Always validate keys before merging. concat() stacks DataFrames (axis=0 for rows, axis=1 for columns) without needing a key.

merge(on, how='inner/left/right/outer') — SQL-style join on key col
left_on/right_on — when key column names differ between DataFrames
validate='1:1' — raises error if keys are not unique; prevents silent row explosion
concat([df1,df2], ignore_index=True) — stack rows; no key needed
# Inner join — only matching keys pd.merge(orders, customers, on='cust_id') # Left join — keep all orders pd.merge(orders, customers, on='cust_id', how='left') # Different key names pd.merge(df1, df2, left_on='emp_id', right_on='employee_id') # Validate — catch key duplication early pd.merge(df1, df2, on='id', validate='1:1') # Stack rows pd.concat([jan, feb, mar], ignore_index=True)
Interview Questions
Q1. Explain inner vs left vs outer join with an example.Reveal
Answer: Say orders has ids [1,2,3] and customers has ids [2,3,4]. inner: only [2,3] (both tables). left: [1,2,3] — id=1 gets NaN customer info. outer: [1,2,3,4] — all rows from both, NaN where no match. Use outer for reconciliation to find rows that exist in only one table.
Q2. What causes duplicate rows after a merge and how do you prevent it?Reveal
Answer: Duplicate keys in the join column. If df1 has 3 rows with id=5 and df2 has 2 rows with id=5, the merge produces 3×2=6 rows for that key. Prevention: df['key'].duplicated().any() before merging, or use validate='1:1' in merge to raise an error if keys are non-unique.
Q3. Difference between merge() and concat()?Reveal
Answer: merge() is SQL join — combines rows based on matching key values, changes both shape dimensions. concat(axis=0) stacks rows of same-structure DataFrames (like UNION in SQL). concat(axis=1) stacks columns side-by-side, aligning on index. concat needs no key column.

Apply, Map & Vectorization
Advanced⌄
📖 Explanation

apply() runs a Python function row-by-row — flexible but 10–100× slower than vectorised ops because it breaks out of NumPy's C layer. Rule: if you can express it as arithmetic, a comparison, or a built-in method, never use apply. np.where() replaces if/else; np.select() replaces if/elif/else chains. map() is element-wise on a Series — best for value replacement with a dict.

vectorized ops — df['a']+df['b'], col*2; C-level speed; always prefer
np.where(cond, val_T, val_F) — vectorized if/else
np.select(conditions, choices, default) — vectorized if/elif/else
map(dict) — element-wise Series replacement; NaN for unmapped values
apply(axis=1) — last resort; only for complex multi-column logic
import numpy as np # SLOW — breaks out of C layer df['tax'] = df.apply(lambda r: r['price']*0.18, axis=1) # FAST — vectorised (100x+ faster) df['tax'] = df['price'] * 0.18 # np.where — vectorised if/else df['result'] = np.where(df['score']>50, 'Pass', 'Fail') # np.select — vectorised if/elif/else conds = [df['score']>90, df['score']>75, df['score']>50] df['grade'] = np.select(conds, ['A','B','C'], default='F') # map — dict replacement df['code'] = df['gender'].map({'M':0, 'F':1})
Interview Questions
Q1. Why is apply() slow and how do you replace it?Reveal
Answer: apply() iterates row-by-row in Python — each row is extracted as a Series, function called, result collected. This Python overhead is 10–100× slower than NumPy C operations. Replacements: simple arithmetic → vectorised op; if/else → np.where(); multi-condition → np.select(). Only keep apply for genuinely complex multi-column logic with no vectorised equivalent.
Q2. Difference between apply() and map() on a Series?Reveal
Answer: map() is element-wise on a Series; best for simple value replacement using a dict or function. map({'a':1,'b':2}) returns NaN for unmapped values. apply() is more flexible — can return complex objects, works on DataFrames with axis=0/1. Rule: use map() for dict/value replacement; use apply() only when map isn't enough.
Q3. How do you create a grade column from 4 conditions without using apply?Reveal
Answer: Use np.select(): define a list of boolean conditions (evaluated top-to-bottom, first True wins) and a list of return values. conds=[score>90, score>75, score>60, score>50]; vals=['A','B','C','D']; df['grade']=np.select(conds, vals, default='F'). Fully vectorised — works on millions of rows instantly.

String Operations (.str accessor)
Advanced⌄
📖 Explanation

The .str accessor gives vectorised Python string methods on a Series — same API as Python strings but operating on entire columns at once. str.extract(pattern) uses regex capture groups to parse structured text (emails, logs, phone numbers). str.get_dummies(sep) one-hot encodes multi-label columns like "Python,SQL,R". NaN values propagate safely through most str methods — except str.contains() which needs na=False.

str.lower/upper/strip/replace/title — vectorised; chainable
str.contains(pat, case, na=False) — regex/literal filter; na=False is critical
str.extract(r'(group)') — regex capture group → new column
str.split(pat, expand=True) — split into multiple columns
str.get_dummies(sep=',') — one-hot for multi-label strings
# Clean text df['name'] = df['name'].str.strip().str.title() # Extract domain from email df['domain'] = df['email'].str.extract(r'@(.+)\.') # Split name into first + last df[['first','last']] = df['name'].str.split(' ', expand=True) # One-hot: "Python,SQL,Pandas" → 3 columns skills = df['skills'].str.get_dummies(sep=',') df = pd.concat([df, skills], axis=1) # Remove non-digits from phone df['phone'] = df['phone'].str.replace(r'\D', '', regex=True)
Interview Questions
Q1. How would you extract the domain name from an email column?Reveal
Answer: df['domain'] = df['email'].str.extract(r'@(.+)\.') — the (.+) capture group matches everything between @ and the last dot. Alternative: df['email'].str.split('@').str[1].str.split('.').str[0] — more readable but less elegant.
Q2. What is str.get_dummies() and when is it better than pd.get_dummies()?Reveal
Answer: str.get_dummies(sep) handles multi-label cells (e.g., 'Python,SQL,R'). pd.get_dummies() can't — it would treat 'Python,SQL' as a single category. Use str.get_dummies when one row can have multiple values in one cell (skills, tags, genres). Use pd.get_dummies for single-value categorical columns.
Q3. What happens if you use str methods on a column with NaN values?Reveal
Answer: Most str methods propagate NaN safely (NaN in → NaN out, no error). Exception: str.contains() returns NaN for NaN inputs — using that as a filter raises ValueError. Fix with na=False. Best practice for heavy string work: df['col'].fillna('').str.lower().

Datetime Operations (.dt accessor)
Advanced⌄
📖 Explanation

Always convert string dates to datetime64 with pd.to_datetime() — using errors='coerce' converts bad dates to NaT instead of raising errors. The .dt accessor then unlocks all date components (year, month, weekday, quarter) and arithmetic. resample() is GroupBy for time series — group by period ('D','W','ME','QE') and aggregate. Subtracting two datetime columns gives a Timedelta; use .dt.days for integer days.

pd.to_datetime(col, errors='coerce') — parse; coerce = bad dates → NaT
.dt.year/month/day/weekday/quarter/day_name() — extract components
(end - start).dt.days — Timedelta to integer days
resample('ME', on='date').sum() — monthly aggregation
# Parse — always first step df['date'] = pd.to_datetime(df['date'], errors='coerce') df['year'] = df['date'].dt.year df['weekday'] = df['date'].dt.day_name() # 'Monday' df['quarter'] = df['date'].dt.quarter df['is_wknd'] = df['date'].dt.weekday >= 5 # Days between two dates df['tenure'] = (df['end'] - df['start']).dt.days # Monthly total using resample df.resample('ME', on='date')['sales'].sum()
Interview Questions
Q1. What does errors='coerce' do in pd.to_datetime()?Reveal
Answer: Default (errors='raise') raises ValueError if any value can't be parsed. errors='coerce' silently converts invalid dates to NaT (Not a Time) instead. Essential for real data that mixes valid dates with 'N/A', empty strings, or impossible dates like '99/99/9999'. After coercing, use df['date'].isnull().sum() to count failures.
Q2. How do you group a time series by month and sum sales?Reveal
Answer: Two approaches: (1) df.resample('ME', on='date')['sales'].sum() — idiomatic time-series approach, requires datetime column. (2) df.groupby(df['date'].dt.to_period('M'))['sales'].sum() — more explicit, easier to extend to multi-column aggs. resample is preferred for pure time-series work.
Q3. How do you calculate business days between two date columns?Reveal
Answer: np.busday_count(df['start'].dt.date, df['end'].dt.date). Pandas has no built-in business day difference. .dt.date extracts Python date objects (required by busday_count). For custom holidays/weekends use np.busdaycalendar(). For simple calendar days: (df['end']-df['start']).dt.days.

Pivot Tables & Reshaping
Advanced⌄
📖 Explanation

pivot_table() is the Pandas equivalent of an Excel pivot — aggregates by row/column groupings. margins=True adds subtotals. pivot() reshapes without aggregating but raises ValueError if the (index, columns) pair has duplicates. melt() is the inverse — it converts wide format (one column per measurement) to long format (one row per measurement). Long format is required by seaborn, plotly, and most ML pipelines.

pivot_table(values, index, columns, aggfunc, margins) — full Excel-style pivot
pivot() — reshape only; raises ValueError on duplicate (index,col) pairs
melt(id_vars, var_name, value_name) — wide → long; required for viz/ML
crosstab(normalize='index') — frequency table with row-wise proportions
# Pivot table — sales by region x product pd.pivot_table(df, values='sales', index='region', columns='product', aggfunc='sum', fill_value=0, margins=True) # melt — wide to long # Before: [id, Jan, Feb, Mar] # After: [id, month, sales] df.melt(id_vars=['id'], var_name='month', value_name='sales') # Frequency table with % per row pd.crosstab(df['gender'], df['survived'], normalize='index')
Interview Questions
Q1. Difference between pivot() and pivot_table()?Reveal
Answer: pivot() reshapes without aggregating — raises ValueError: Index contains duplicate entries if the (index, columns) combination is not unique. pivot_table() handles duplicates by aggregating with aggfunc (default: mean). Rule: try pivot() first; if you get a ValueError about duplicates, switch to pivot_table().
Q2. When would you use melt() and what problem does it solve?Reveal
Answer: melt() converts wide format to long (tidy) format. Use it when: (1) viz libraries like seaborn expect one column for category name and one for value; (2) ML pipelines need one-row-per-observation format; (3) wide monthly/quarterly columns need to become a single 'period' column. Example: [Jan, Feb, Mar] columns → 'month' + 'sales' columns.
Q3. What does normalize='index' do in pd.crosstab()?Reveal
Answer: normalize='index': each row sums to 1.0 (% within each row group). normalize='columns': each column sums to 1.0. normalize=True: overall proportions, each cell as % of grand total. Without normalize: raw counts.

MultiIndex & Advanced Indexing
Advanced⌄
📖 Explanation

A MultiIndex (hierarchical index) has multiple label levels on rows or columns. It arises naturally after groupby or pivot_table. Always call sort_index() after creating a MultiIndex — without sorted index, range slices silently return wrong results. .xs(key, level=) selects by a single level. pd.IndexSlice provides clean syntax for slicing ranges across levels. reset_index() flattens back to regular columns.

set_index(['a','b']).sort_index() — always sort after creating MultiIndex
loc[(outer, inner)] — exact tuple selection
xs(key, level=) — cross-section by one level; drops that level from result
pd.IndexSlice — clean range slicing across levels
df = df.set_index(['year','month']).sort_index() # Exact combination df.loc[(2023, 'Jan')] # Cross-section — all months for 2023 df.xs(2023, level='year') # Range across both levels idx = pd.IndexSlice df.loc[idx[2022:2023, 'Jan':'Mar'], :] # Flatten MultiIndex columns after groupby df.columns = ['_'.join(c).strip() for c in df.columns] df.reset_index()
Interview Questions
Q1. Why must you sort_index() after creating a MultiIndex?Reveal
Answer: Pandas requires the MultiIndex to be lexicographically sorted for range slices to work correctly. Without it: df.loc[2022:2023] may miss rows or return wrong results, and you get PerformanceWarning: indexing past lexsort depth. Always: df.set_index(['a','b']).sort_index().
Q2. After groupby with multiple agg functions, how do you flatten MultiIndex columns?Reveal
Answer: df.columns = ['_'.join(col).strip() for col in df.columns] — joins the two levels with underscore ('salary_mean', 'salary_max'). Better approach: use named aggregation syntax agg(avg_sal=('salary','mean')) which produces flat column names directly and avoids MultiIndex entirely.
Q3. Difference between xs() and loc[] for MultiIndex?Reveal
Answer: loc[(outer, inner)] requires you to specify values at each level. xs(key, level=) selects by one level value regardless of other levels, and drops that level from the result index. Use xs when you want to 'zoom into' one level without specifying all others.

Performance & Memory Optimization
Expert⌄
📖 Explanation

The biggest single win: category dtype on low-cardinality string columns. A 1M-row city column as object uses ~50MB; as category it uses ~1MB (stores integer codes + a small lookup table). Downcasting numerics (int64→int8/16/32, float64→float32) halves or quarters memory. At read time, usecols + dtype is free speed. eval() uses numexpr to evaluate expressions in C without intermediate arrays — faster on large DataFrames.

category dtype — use when nunique/len < 0.5; 90% memory saving
to_numeric(downcast='integer') — auto-selects smallest int type
usecols + dtype at read time — cheapest optimisation; never read what you don't need
eval('expr') — numexpr-backed; no intermediate arrays; faster on large df
# Check memory first df.memory_usage(deep=True).sum() / 1024**2 # MB # Convert low-cardinality strings to category for col in df.select_dtypes('object').columns: if df[col].nunique() / len(df) < 0.5: df[col] = df[col].astype('category') # Downcast numerics df['age'] = pd.to_numeric(df['age'], downcast='integer') df['rating'] = pd.to_numeric(df['rating'], downcast='float') # eval — no intermediate arrays df.eval('profit = revenue - cost - tax', inplace=True)
Interview Questions
Q1. Name 4 concrete strategies to reduce a 5 GB DataFrame's memory.Reveal
Answer: (1) usecols at read time — load only needed columns. (2) category dtype for low-cardinality strings — 50–90% reduction. (3) Downcast numerics — int64→int8/32, float64→float32. (4) chunksize — never hold more rows in RAM than needed. Bonus: Parquet format is 3–10x smaller than CSV.
Q2. When should you NOT use category dtype?Reveal
Answer: When cardinality is high (many unique values). For a column like customer_id or email where nearly every row is unique, category stores a massive lookup table with no memory saving — worse than object. Rule: use category when nunique/len < 0.5. Also note: assigning new values not in the existing categories raises ValueError unless you add them first.
Q3. What is the difference between eval() and a regular Pandas expression?Reveal
Answer: Regular: df['a'] + df['b'] + df['c'] creates two intermediate arrays (step1: a+b, step2: +c) — significant memory pressure on large DataFrames. eval('result = a + b + c') compiles the entire expression to C via numexpr and evaluates in one pass — no intermediate arrays, 2–10x faster on >500K rows. Limitation: only supports arithmetic, comparison, and boolean ops.

Window Functions (Rolling & Expanding)
Expert⌄
📖 Explanation

Window functions compute aggregate values over a sliding "window" of rows without reducing DataFrame shape — essential for time series and ML feature engineering. rolling(n) uses the last n rows; first n-1 rows are NaN. expanding() grows from row 1 to current row — cumulative stats. ewm(span) gives exponentially decaying weights — more weight to recent values. shift(n) creates lag features (yesterday's value as a predictor for today). Always sort_values('date') first.

sort by date first — critical; window functions assume chronological order
rolling(n, min_periods) — last n rows; first n-1 are NaN unless min_periods set
expanding() — cumulative from start; equivalent to growing rolling window
shift(n) — lag feature; shift(1) = yesterday; always shift rolling features too
pct_change() / diff() — period-over-period % change / absolute change
df = df.sort_values('date') # always first! df['ma_7'] = df['price'].rolling(7).mean() df['ma_30'] = df['price'].rolling(30).mean() df['vol_30'] = df['price'].rolling(30).std() # Lag features for ML df['lag_1'] = df['sales'].shift(1) # yesterday df['lag_7'] = df['sales'].shift(7) # last week # Shift rolling feature to avoid leakage df['ma7_lag1'] = df['sales'].rolling(7).mean().shift(1) df['growth'] = df['sales'].pct_change() * 100 df['cum_sales'] = df['sales'].expanding().sum()
Interview Questions
Q1. Difference between rolling() and expanding()?Reveal
Answer: rolling(n): fixed window of last n rows — captures recent trend. expanding(): grows from row 1 to current row — cumulative stats. Use rolling for moving averages, recent volatility. Use expanding for year-to-date, running totals, all-time max. expanding().mean() is equivalent to the cumulative mean at each row.
Q2. How do you create lag features for time series ML without data leakage?Reveal
Answer: Use shift(n) after sorting by date. To avoid leakage, always shift rolling/expanding features by at least 1: df['sales'].rolling(7).mean().shift(1) gives the 7-day MA of values up to yesterday — not including today's value. If you use rolling(7).mean() without shift, today's own sales value leaks into the feature.
Q3. What is min_periods in rolling() and when should you set it?Reveal
Answer: By default, rolling(7) requires exactly 7 values in the window — first 6 rows return NaN. min_periods=1 produces results from row 1 using however many values are available. Use min_periods=1 when you want best-available stats at the start of a series. Keep default when statistical stability is more important than coverage.

Pandas for ML Preprocessing
Expert⌄
📖 Explanation

get_dummies(drop_first=True) one-hot encodes categoricals; drop_first removes one column to prevent the dummy variable trap (perfect multicollinearity in linear models). cut() bins continuous variables into user-defined equal-width intervals; qcut() creates equal-frequency bins (each bin has the same number of rows — better for skewed distributions). clip() caps outliers without dropping rows. pipe() chains preprocessing steps into a clean, readable, testable pipeline.

get_dummies(drop_first=True) — one-hot; drop_first prevents multicollinearity
cut(bins, labels) — equal-width; user-defined breakpoints
qcut(q, labels) — equal-frequency; robust for skewed data
clip(lo, hi) — cap outliers; preserves rows unlike dropna
pipe(func) — chain steps; each func takes df, returns df
# One-hot encode (drop_first avoids dummy trap) df = pd.get_dummies(df, columns=['city','gender'], drop_first=True, dtype=int) # Bin age into groups df['age_grp'] = pd.cut(df['age'], bins=[0,18,35,55,100], labels=['teen','young','mid','senior']) # Cap outliers at 5th / 95th percentile lo, hi = df['salary'].quantile([.05,.95]) df['salary'] = df['salary'].clip(lo, hi) # pipe — clean preprocessing pipeline def clean(df): return df.drop_duplicates().fillna(0) df = df.pipe(clean).pipe(pd.get_dummies, columns=['city'], drop_first=True)
Interview Questions
Q1. Why use drop_first=True in get_dummies? What is the dummy variable trap?Reveal
Answer: With k categories you only need k-1 binary columns — the dropped category is perfectly predictable when all others are 0. Including all k creates perfect multicollinearity: linear regression has a singular matrix and can't be solved uniquely. Tree-based models (XGBoost, Random Forest) don't need drop_first. Linear/logistic regression and SVM do.
Q2. Difference between cut() and qcut()?Reveal
Answer: cut(): equal-width bins. You define the breakpoints. Problem: skewed data can put 90% of rows in one bin. qcut(q=4): equal-frequency bins — each bin gets 25% of rows. Better for skewed data, creating balanced groups for comparison. Use cut when bin edges have domain meaning (generation groups); use qcut when you need balanced groups.
Q3. What is pipe() and why is it better than sequential reassignment?Reveal
Answer: Without pipe: df=step1(df); df=step2(df); df=step3(df) — noisy. With pipe: df.pipe(step1).pipe(step2).pipe(step3) — clean, chainable, each step is a function taking and returning a DataFrame. Benefits: easy to add/remove/reorder steps, easy to unit-test each step, clear data lineage. The Pandas equivalent of Unix pipes.
